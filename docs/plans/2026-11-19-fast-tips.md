# Fast Tips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tip="…"` on a bracketed span or a link shows its note after a delay the author sets in front matter or on the element, using CSS only. A plain `title` keeps the browser's own tooltip.

**Architecture:** Chips and LinkAttrs record a tip as two internal attributes on the host element. A finishing pass, `writeTips`, turns them into the wrap/host/tooltip markup. Convert runs it after every transform, `linkDrop` and `linkRewrite` included, and `Site.wrap` runs it on the shell. A page that has a tip gets a small embedded `tip.css` with the rules that make tips work, whatever its style, plus its `tip-delay` as a custom property on `main.md2html`. `default.css` adds only the look.

**Tech Stack:** Go 1.26; `golang.org/x/net/html`; embedded CSS (`theme.go`); chromedp in the separate `e2e/` module.

**Spec:** `docs/specs/2026-11-19-fast-tips-design.md`. §3 covers writing a tip, §4 the delay, §5 the markup and where it comes from, §6 the look, §7 leaks and §8 warnings.

## Global Constraints

- Work on `feat/keep-span-titles` in the user's checkout. Conventional prefixes. Commit bodies are wrapped at 72 columns and start from what was wrong before. No attribution trailer. Nothing is pushed.
- No exported API changes. `Builtins()`, `Chips()` and `LinkAttrs(warn)` keep their signatures.
- The internal attributes are `md2html-tip` (the note) and `md2html-tip-delay`. Neither has a `data-` or `aria-` prefix, so no attribute block can set them. `writeTips` removes both, so neither ever reaches output.
- Class names, exactly: `md2html-tip-wrap`, `md2html-tip-host` and `md2html-tooltip`. Ids are `md2html-tooltip-N`, from 1 in document order per tree. The custom property is `--md2html-tip-delay`. The charts' `md2html-tip` class and its rules are untouched.
- A valid delay matches `^[0-9]+(\.[0-9]+)?m?s$`, and the default is `100ms`.
- Precedence is the element, then the page's front matter, then the shell's front matter, then the default.
- Every warning has an entry in `docs/guide/warnings.md` (`TestEveryWarningIsInTheGuide`), raised as `warn(fmt.Sprintf(...))` where it is built, so the scanner sees it.
- Run `gofmt -l .` (empty output), `go vet ./...` and `go test ./...` before every commit.

## Review Focus

1. **A tipped link that a site build drops**: `linkDrop` must keep the tip on the unwrapped text, as a focusable span host, not orphan the note. Pinned in Task 2.
2. **A style with `"base": "none"`, and a caller's own `Options.CSS`**: the tip must still be hidden until hover. With the rules missing, the note shows as a second copy in the text. Pinned in Task 3.
3. **A tip in a heading of a site page**: the search index's heading text and the first paragraph's text must not contain the note. Pinned in Task 4.
4. **Shell and page both with tips**: the ids clash (both start at `md2html-tooltip-1`), and after renumbering, the shell's `aria-describedby` must name the shell's renamed tooltip. Pinned in Task 2.
5. **`tip-delay` values that try CSS**: `0ms; background:red` and `calc(1s)` are refused with a warning in front matter and on an element, and never reach a `style` attribute or the stylesheet. Pinned in Tasks 1 and 3.

- [ ] **Step 3: Implement**

- **`writeTips`:**
  1. Walk the tree, collecting elements that carry `tipAttr`.
  2. For a host with an `<a>` ancestor that isn't itself the host: remove both attributes and `warn(fmt.Sprintf("bracketed span [%s]: a tip inside a link is dropped; put the tip on the link", text))`, where `text` is the host's text.
  3. Otherwise build the wrap in the host's place, with the host and then the tooltip inside it. The tooltip's text is the note, as a text node. Add `md2html-tip-host` to the host's classes, `aria-describedby`, and `tabindex="0"` unless the host is an `<a>`. Append `--md2html-tip-delay: V` to its style, joined with `; ` after any existing style.
  4. Remove both internal attributes.
- **Convert:** calls `writeTips(root, opt.Warn)` after the transform loop. That way it follows the caller's transforms, `linkDrop` and `linkRewrite`.
- **`Site.wrap`:** calls `writeTips(shell, s.shellWarn)` on the shell's tree after the shell's transforms and before `renumberShellIDs`.
- **`renumberShellIDs`:** rewrites `aria-describedby` tokens through `renamed`, as it does `href="#…"`.
- **`linkDrop`:** when an `<a>` it drops carries `tipAttr`, it replaces the `<a>` with a `<span>` holding the `<a>`'s children and both internal attributes, instead of the bare children.

- [ ] **Step 3: Implement**

`tip.css` holds only the mechanics:

- the wrap is `position: relative; display: inline`;
- the tooltip is absolutely placed above its host, centred with `left: 50%` and `translate: -50% 0`, `max-width: 30ch` and `width: max-content`;
- it is `visibility: hidden` with `transition: visibility 0s linear 0s` by default, and `visible` with `transition-delay: var(--md2html-tip-delay, 100ms)` on the host's `:hover` and `:focus-visible`, so hiding is immediate;
- inside `@supports (position-try-fallbacks: flip-block)`, `position-try-fallbacks: flip-block`;
- in print: `position: static; visibility: visible`, with `::before { content: " (" }` and `::after { content: ")" }`.

Reduced motion keeps the delay, since it's a pause, not a motion, and removes any fade the look adds.

The look in `default.css`: `background: var(--chart-surface); color: var(--fg); border: 1px solid var(--rule)`, a small radius and padding, a font size around `0.85rem`, and `.md2html-tip-host:not(a) { cursor: help; }`.

Front matter's `tip-delay` is read through `tipDelayRule`. An invalid page value warns `front matter tip-delay %q is not a time such as 150ms; using the site's or the default delay` and falls through to the shell's value. An invalid shell value goes through `shellWarn`. Add the guide entry.
