# fig Nested Layouts Implementation Plan

**Goal:** Make `cols` and `split` item kinds that can sit anywhere an item
can, and give panel position a card layer of its own that an accented item
tints.

**Architecture:** The figure-level layout switch in `renderFig` moves into
one `(*figRenderer).layout` method that both the figure and the new `cols`
and `split` item cases call, so a nested layout is byte-identical to a
figure-level one. Positional legality (`boundary`, widened `weight`, the
sole-item rule) is enforced in `validateItems`/`validateFig`, exactly as
`weight` and `items` already are. `panel()` gains two classes derived from
the item it wraps; the stylesheet draws a card on `.fig-panel`, tints it for
`fig-panel-accent`, skips it for `fig-panel-arrow`, and moves the accent
ring's gap onto a `--fig-surface` token the card sets.

**Tech Stack:** Go 1.27.1, goldmark 1.8.6, `gopkg.in/yaml.v3`,
`golang.org/x/net/html`, chromedp (separate `e2e` module).

**Spec:** `docs/specs/2026-09-14-fig-nested-layouts-design.md`

## Global Constraints

- Work directly on `main`. One commit per task.
- Module is `github.com/AdamF-G/md2html`; root package is `md2html`, flat
  layout, no `internal/` packages added.
- **No new dependencies.** `go.mod` and `e2e/go.mod` must be untouched.
- Nothing may fail a conversion. Every fault degrades to
  `<pre><code class="language-fig">` with the raw body, plus exactly one
  `Warn`.
- **Markup changes in exactly two places:** a panel whose item carries
  `accent` gains `fig-panel-accent`; a panel whose item is an arrow gains
  `fig-panel-arrow`. Every other figure must emit the bytes it emits today.
- The stylesheet defines **no new colour tokens**. The tint is
  `color-mix(in srgb, var(--accent) 12%, var(--bg))` — 12%, not 8%.
- No `:has()` selectors. No JavaScript in the page.
- Validation messages follow the shipped shape `<path> carries <field>,
  which only a <list> takes`, except the two count/position faults whose
  exact wording is given in Tasks 1 and 2.
- Markup and validation tests go through `figConvert` (placeholder
  stylesheet `/**/`). Only browser tests use the real stylesheet.
- Run `go test ./...` at the repo root before every commit. Browser tests
  run with `just e2e` (or `cd e2e && go test -count=1 ./...`) and need a
  local Chrome or Chromium.
- Every author-facing text field renders through `figRenderer.inline`.
  Class names are generated by this code and never escaped.

```go
// layout renders a run of items in one of the three layouts. A figure calls
// it with its own layout and boundary; a cols or split item calls it with
// its own list, so a nested layout is the same markup as a figure-level one
// rather than a second implementation of it. Any kind other than cols or
// split is rows, which is what an unset figure layout means.
func (r *figRenderer) layout(kind string, items []figItem, boundary string) string {
	var b strings.Builder
	switch kind {
	case "cols":
		b.WriteString(`<div class="fig-cols">`)
		for _, it := range items {
			b.WriteString(r.panel(it))
		}
		b.WriteString(`</div>`)
	case "split":
		// Validation has already guaranteed exactly two items, for a split
		// figure and a split item alike.
		b.WriteString(`<div class="fig-split">`)
		b.WriteString(r.panel(items[0]))
		b.WriteString(`<div class="fig-boundary">`)
		b.WriteString(r.inline(boundary))
		b.WriteString(`</div>`)
		b.WriteString(r.panel(items[1]))
		b.WriteString(`</div>`)
	default:
		b.WriteString(`<div class="fig-rows">`)
		b.WriteString(r.items(items))
		b.WriteString(`</div>`)
	}
	return b.String()
}
```

In `figrender.go`, in `item()`, add two cases after the `Lanes` case, before

```go
// custom property rather than a raw flex-grow so a caller's --css
```

// figColorMath parses the two serializations getComputedStyle uses for an
// sRGB colour — rgb()/rgba() for a token, color(srgb ...) for a color-mix()
// result — and computes WCAG contrast from them. The card tests assert
// floors rather than colours: a palette change that keeps a panel readable
// passes, and one that does not fails.
const figColorMath = `
	function channels(s) {
		let m = s.match(/^rgba?\(([^)]*)\)$/);
		if (m) return m[1].split(/[\s,\/]+/).filter(Boolean).slice(0, 3).map(v => parseFloat(v) / 255);
		m = s.match(/^color\(srgb ([^)]*)\)$/);
		if (m) return m[1].split(/[\s\/]+/).filter(Boolean).slice(0, 3).map(parseFloat);
		throw new Error("unparsed colour: " + s);
	}
	function luminance(s) {
		const lin = c => c <= 0.03928 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4);
		const [r, g, b] = channels(s).map(lin);
		return 0.2126 * r + 0.7152 * g + 0.0722 * b;
	}
	function contrast(a, b) {
		const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x);
